# Castle notation - castles, towers, and signed counts

## Two kinds of object, two argument orders

The wiki counts two related objects, and they are indexed differently.

- A **castle** of width `w` and height `h` is a skyline `(c_1, …, c_w)` with `1 ≤ c_i ≤ h` and some `c_i = h` ([[castle-polyomino](pages/castle-polyomino.md)]). Castle counts put **width first**: `A(w, h)`.
- Removing the bottom row of a castle leaves **towers**. Towers on a base of length `L` are given by their column heights `c_1, …, c_L ∈ {0, …, k}` above the base, where 0 means nothing above the bottom row. Towers may have height 0; castles may not. Tower counts put **tower height first**: `T(k, L)`, `P(k, L)`.[^1]

Removing the bottom row maps the castles of width `w` and height at most `h` one-to-one onto the towers of height at most `h − 1` on a base of length `w`. So the translation between the two is always

```
tower height  k  =  h − 1        (castle height h)          base length  L  =  w        (castle width w)
```

## The core symbols

| symbol | meaning | arguments |
|---|---|---|
| `A(w, h)` | the number of castles of width `w` and height `h`: `h^w − (h−1)^w` | width, height |
| `A^e(w, h)`, `A^o(w, h)` | the number of castles of width `w` and height `h` with an **even** and with an **odd** number of blocks, so `A = A^e + A^o`. `A^e` is the Project Euler 502 count, which the problem statement writes `F(w, h)` | width, height |
| `S(w, h)` | the **signed count** `Σ (−1)^{blocks}` over the castles of width `w` and height `h`: `S = A^e − A^o = P(h−2, w) − P(h−1, w)`, so `A^e = (A + S)/2` and `A^o = (A − S)/2` | width, height |
| `A_X(w, h)`, `A^e_X`, `A^o_X`, `S_X` | the same counts over the castles of a family X, with an upright subscript that names the family, as in `A_ridge(w, h)`. When the family's definition fixes the height, `A_X(w)`, and the page says which height | width, height |
| `T(k, L)` | the number of towers of height at most `k` on a base of length `L`: `(k + 1)^L` | tower height, base length |
| `P(k, L)` | the **signed tower count** `Σ (−1)^{blocks}` over the same towers. The bare letter `P` is reserved for it; the Pell numbers are starred, `P⋆_n` (section *Other meanings of P, T, and other shared letters on the wiki*) | tower height, base length |
| `P_X` | `P` over the towers of a family X, as `P_F(w)` over the Fibonacci towers (section *Other meanings of P, T, and other shared letters on the wiki*) | base length |
| `P_even(k, L)`, `P_odd(k, L)` | `P` restricted to towers whose last column is even / odd ([[tower-parity-sectors](pages/tower-parity-sectors.md)]) | tower height, base length |
| `char_k` | characteristic polynomial of the recurrence of `P(k, ·)` in `L` | tower height |

`T` counts towers and `P` is its signed version; both are tower counts, indexed by tower height.[^1] `P` adds up over towers and `S` over castles, and the two signs are opposite: a castle has one block more than its towers, so the even-block castles stand on the odd-block towers. A sum over castles is never written with `P`. The Project Euler sources and notes write `F(w, h)` for `A^e(w, h)` and `odd(w, h)` or `F_odd(w, h)` for `A^o(w, h)`; quotes keep their notation, and the wiki's own text writes `A^e` and `A^o`.

## The one formula where both orders meet

For `h ≥ 2`,

```
A^e(w, h)  =  [ A(w, h) + S(w, h) ] / 2
           =  [ h^w − (h−1)^w  −  P(h−1, w)  +  P(h−2, w) ] / 2
```

`A`, `A^e` and `S` are castle counts (width first), and the two `P` terms are tower counts (tower height first) at tower heights `h − 1` and `h − 2` and base length `w` ([[castle-counting-formula](pages/castle-counting-formula.md)]).

**Worked case `h = 2`.** `P(0, L) = 1`, since the only tower of height 0 is empty and has no blocks, so

```
A^e(w, 2)  =  [ 2^w − 1 − P(1, w) + 1 ] / 2  =  ( 2^w − P(1, w) ) / 2
```

At `w = 2`, `P(1, 2) = −2` gives `A^e(2, 2) = (4 + 2)/2 = 3`: the skylines `(1, 2)`, `(2, 1)` and `(2, 2)`, each with two blocks.[^2] Towers of height at most 1 are binary strings, and each run of 1s is one block in row 2 of the castle. `P(1, ·)` enters `A^e(w, 2)` as `P(h−1, w)` and `A^e(w, 3)` as `P(h−2, w)`.

## Trivial and first cases

| tower height `k` | castle heights that use it | `P(k, L)` for `L = 0, 1, 2, …` |
|---|---|---|
| 0 | `h = 2` (as `P(h−2, w)`) | `1` for every `L` |
| 1 | `h = 2` (as `P(h−1, w)`), `h = 3` (as `P(h−2, w)`) | `1, 0, −2, −4, −4, 0, 8, 16, …` = `Re((1+i)^{L+1})` |
| 2 | `h = 3`, `h = 4` | `1, 1, 3, 9, 19, 33, 59, 121, …` |

## Reading conventions

- **"Height" means castle height `h`** unless the sentence is about towers. "Towers of height at most 1" and `P(1, L)` refer to tower height, and the castle height is given where it matters. A castle of height `h` has a column of height `h`; the wiki writes "height `h`", not "exact height".
- **`P(k, w)`** on a few pages ([[fractional-width-and-height](pages/fractional-width-and-height.md)], [[mod-9-equidistribution](pages/mod-9-equidistribution.md)]) is `P(k, L)` at base length `L = w`, the castle width, as it appears in the formula for `A^e`.
- **Generating functions.** `E_k(x) = Σ_L T(k, L) x^L` and `P_k(x) = Σ_L P(k, L) x^L` are the tower generating functions in `x`, written with their argument ([[castle-counting-formula](pages/castle-counting-formula.md)], [[generalized-dyck-grammar](pages/generalized-dyck-grammar.md)]). With `y` marking blocks, `E_k(x, y)` counts the towers of height at most `k` by width and blocks, so `E_k(x) = E_k(x, 1)` and `P_k(x) = E_k(x, −1)`, and `E_∞(x, y)` counts the towers of every height ([[generalized-dyck-grammar](pages/generalized-dyck-grammar.md)], section *Counts*). [[castle-q-bessel-closed-form](pages/castle-q-bessel-closed-form.md)] writes the same function as `E_∞(u, x, q)` at `q = 1`, with `u` for width and `x` for blocks.

## Sandpile symbols

The sandpile pages run grains on the castle graph (cells as vertices, edge-sharing cells joined) with a **sink** where grains vanish: one chosen cell in the **sink model**, or the whole bottom row, the ground, in the **tide model** ([[sandpile-group](pages/sandpile-group.md)]). Heights count grains from 0, and a cell topples when it holds at least as many grains as it has neighbors.

| symbol | meaning | where |
|---|---|---|
| `L` | the Laplacian `D − A` of the castle graph: `D` the diagonal of cell degrees, `A` the adjacency matrix (not the castle count `A(w, h)`) | [[hear-the-shape-seminar](pages/hear-the-shape-seminar.md)], [[sandpile-group](pages/sandpile-group.md)] |
| `L̃` | the **reduced Laplacian**: `L` with the sink's rows and columns deleted (one cell's row and column in the sink model, every bottom-row cell's in the tide model, where each remaining cell keeps its full degree). Toppling cell `v` subtracts row `v` of `L̃` | [[sandpile-group](pages/sandpile-group.md)], [[castle-avalanches](pages/castle-avalanches.md)] |
| `Δ` | Dhar's toppling matrix of a general abelian sandpile; for a castle `Δ = L̃`. Stable heights differ by a shift between sources: Dhar `1..Δ_vv`, Chau-Cheng `≤ 0` (critical height moved to 0), the wiki `0..deg − 1`. Chau 1993 writes toppling as `h_i → h_i − Δ_ji`, the transpose, which is the same for a symmetric castle `L̃` | [[dhar-1990-self-organized-critical-sandpile](pages/dhar-1990-self-organized-critical-sandpile.md)] |
| `K(G)`, `K` | the sandpile group `Z^{n_live} / L̃ Z^{n_live}` of the recurrent configurations, with `n_live` the number of cells outside the sink; its order is `det L̃`, which by the matrix-tree theorem is the number of spanning trees of the castle graph with the sink cells merged into one vertex | [[sandpile-group](pages/sandpile-group.md)], [[sandpile-census](pages/sandpile-census.md)] |
| `L̃⁻¹` | expected topplings: entry `(v, u)` is the mean number of topplings at `u` caused by a grain at `v` in the steady state (Dhar's `G = Δ⁻¹`); the mean avalanche size is the average of its row sums | [[castle-avalanches](pages/castle-avalanches.md)], [[dhar-1990-self-organized-critical-sandpile](pages/dhar-1990-self-organized-critical-sandpile.md)] |
| `a_v` | Dhar's grain operator "add a grain at `v`, then stabilize"; the operators commute, and the order of `a_v` is the clock period | [[sandcastle-clock](pages/sandcastle-clock.md)], [[dhar-1990-self-organized-critical-sandpile](pages/dhar-1990-self-organized-critical-sandpile.md)] |

| `W`, `p_v` | Dhar's transition matrix `W = Σ_v p_v a_v` on the stable configurations, one grain per step; `p_v` is the chance the grain lands on `v`, uniform over the cells outside the sink on the wiki | [[sandcastle-relaxation](pages/sandcastle-relaxation.md)], [[dhar-1990-self-organized-critical-sandpile](pages/dhar-1990-self-organized-critical-sandpile.md)] |
| `n_live` | the number of cells outside the sink: cells − 1 in the sink model, cells − width in the tide model | [[sandcastle-relaxation](pages/sandcastle-relaxation.md)] |
| `ψ`, `λ(ψ)` | a character of `K`, `ψ(e_v) = exp(2πi φ_v)` with `φ ∈ L̃⁻¹ Z^{n_live}` (Dhar's phases in turns), and its eigenvalue of `W`, `(1/n_live) Σ_v ψ(e_v)`; `ψ` because `χ` is the sign character and the 1-smooth determinant | [[sandcastle-relaxation](pages/sandcastle-relaxation.md)] |
| `λ*`, `t_rel` | the largest `\|λ(ψ)\|` over nontrivial characters, and the relaxation time `−1/ln λ*` in grains; `λ*` is not the 1-smooth eigenvalue `λ_k` | [[sandcastle-relaxation](pages/sandcastle-relaxation.md)] |
| `stab(·)` | stabilization: topple until no cell is unstable | [[sandpile-identity](pages/sandpile-identity.md)] |
| `ln det L̃` | the entropy of the steady state (uniform on `det L̃` recurrent piles), written in words on the wiki, not as `S` | [[sandpile-group](pages/sandpile-group.md)] |

**Avalanche statistics.** Dynamical quantities are written in words, because the source papers' letters (`T`, `D`, `F`, `S`, `L`) are core castle symbols here.

| written as | meaning | the source papers wrote |
|---|---|---|
| avalanche **size** | number of topplings caused by one grain | `s` (BTW), `⟨T⟩` for its mean (Dhar) |
| avalanche **duration** | number of rounds, one round toppling every unstable cell at once | `T` (BTW, "lifetime"), `τ` (Dhar) |
| size distribution | probability of an avalanche of a given size; `∼ size^{−τ}` | `D(s)` (BTW) |
| weighted duration distribution | duration distribution weighted by size/duration; `∼ duration^{−α_w}` | `D(T)`, exponent `α` (BTW) |
| toppling rate, power spectrum | topplings per round over time, and its spectrum `∼ frequency^{−β}` (1/f noise when `β ≈ 1`) | `F(t)`, `S(f)` (BTW) |
| `τ`, `α_w`, `β`, `γ_g` | size exponent, weighted-duration exponent, spectral exponent, growth exponent (size `∼` duration`^{1+γ_g}`) | `τ`, `α`, `β`, `γ` (BTW) |
| `d`, `d_f` | lattice dimension, fractal dimension of avalanches | `D`, `d` (BTW); `d` (Dhar) |
| `ℓ` | side of a square (or `ℓ × ℓ` rectangle) lattice | `N`, `L` (BTW), `L` (Dhar) |
| grains, threshold `deg` | grains on a cell, toppling when a cell holds at least `deg` | `z`, `z_c` (BTW, read as a slope), `z_i ≤ Δ_ii` (Dhar) |

## Weights, transfer matrices, and path models

The block weight, the semi-perimeter, and the Motzkin-path readings add a second layer of symbols. They keep the two argument orders of the section *Two kinds of object, two argument orders*: tower quantities are indexed by tower height `k`, castle quantities by width and castle height.

| symbol | meaning | where |

| `M_k(t)` | block-weighted tower transfer matrix on tower heights `0, …, k` (size `k + 1`, the castle height bound), entry `t^max(0, b − a)` (rises); the weighted tower sum is `e_0ᵀ M_k(t)ᴸ 𝟙` | [[castle-sign-kms-matrix](pages/castle-sign-kms-matrix.md)] |
| `M_k` | the signed transfer matrix of [[tower-parity-sectors](pages/tower-parity-sectors.md)], entry `(−1)^max(0, a − b)` (descents): the transpose of `M_k(−1)`. **Height bookkeeping for matrices.** A tower-height matrix (`M_k(t)`, `K(ρ)`, `M_k`) has size `k + 1` = the castle height bound `h`. A castle-height strip (the Motzkin strip, the Pell strip of [[pell-castle-strip](pages/pell-castle-strip.md)], the ridge strip `R_h`) has `h` states, heights `1, …, h`. Both have `h` states; they differ in whether the states are labeled from 0 or from 1.

**Parity words.** "Even-block" always means the PE 502 parity. `A^e(w, h)` counts castles of height `h`; a count over all heights (for example the even-block Motzkin-path castles) is described in words, not written `A^e`.
